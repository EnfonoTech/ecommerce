Integration Flow — Call Order
Only ONE call direction needs the website to act as a client. The other direction, ERPNext calls the website.
ERPNext: Item saved
→
Website: /webhooks/product-sync (you receive)
Website: checkout paid
→
ERPNext: create_sales_invoice (you call)
Website: return / cancellation
→
ERPNext: create_credit_note (you call)
ERPNext: invoice/credit note submitted
→
Website: /webhooks/product-sync (stock update, you receive)
1

Item catalog — nothing to call, you receive it

ERPNext pushes item creates/updates/deletes/price/stock changes to your /webhooks/product-sync endpoint automatically, whenever staff edits an Item in ERPNext. You don't poll or request anything for this — just implement the receiver (already working on your side).

2

Customer completes checkout on the website

The moment payment succeeds (or the order is otherwise confirmed), your backend calls ERPNext's create_sales_invoice endpoint — see below.

3

ERPNext creates/reuses the Customer, creates and SUBMITS a Sales Invoice

Unlike a Sales Order, the invoice is submitted immediately with update_stock=1 — stock deducts in the same call, and the item's new stock figure is pushed to your /webhooks/product-sync receiver right after, in real time.

4

Customer returns an item, or the order is cancelled

Call create_credit_note with the original invoice name. Stock and accounting reverse automatically; the reversed stock is pushed to you the same way.

Create Sales Invoice — you call ERPNext
Call this on checkout completion. Per the BRD, this creates and SUBMITS an invoice (not a draft Sales Order) with automatic stock deduction.
MethodPOST
URLhttps://spicenutrition.enfonoerp.com/api/method/ecommerce.apis.create.create_sales_invoice
HeadersAuthorization: token 8bb68844e36bc72:d82ed035292e259 + Content-Type: application/json

Request body

{
  "customer": "9044120147",
  "customer_details": {
    "name": "John Doe",
    "phone": "9044120147",
    "email": "john@example.com"
  },
  "items": [
    { "item_code": "SD-PR-1000", "qty": 1, "rate": 3499 }
  ],
  "order_ref": "your-internal-order-id",
  "discount_amount": 0,
  "wallet_points": 0
}
FieldDescriptionNote
customerAny stable identifier — the customer's phone number is fine, doesn't need to exist in ERPNext yetRequired
customer_detailsname / phone / email — used to auto-create the Customer on first order, and to find the same Customer again on repeat ordersRequired
items[].item_codeMust match ERPNext's item_code exactly (same codes the product-sync payload uses)Required
order_refYour own order id, stored on the invoice as po_no for cross-reference

Success response (200)

{
  "status": "success",
  "message": "Sales Invoice created and submitted successfully",
  "sales_invoice": {
    "name": "SINV-26-00042",
    "customer": "John Doe",
    "grand_total": 3499,
    "net_total": 3499,
    "outstanding_amount": 3499,
    "update_stock": 1,
    "docstatus": 1
  }
}
Verified working live (Sept 2026): submitted invoice, stock deducted by exactly the ordered qty (checked against the item's Bin quantity before/after), auto-creates the Customer on first order and reuses it by phone/email on repeat orders.
docstatus: 1 means the invoice is final the moment this call returns — there's no separate "confirm" step, no accept/reject workflow. If an order needs a review step before it's binding, hold the call until that review passes; don't call this speculatively.
Create Credit Note — you call ERPNext
Call this for a return or cancellation of an already-submitted Sales Invoice. Reverses stock and accounting automatically.
MethodPOST
URLhttps://spicenutrition.enfonoerp.com/api/method/ecommerce.apis.create.create_credit_note
HeadersSame auth header as above

Request body — full return (everything on the invoice)

{
  "invoice": "SINV-26-00042",
  "reason": "Customer returned the item"
}

Request body — partial return (only some items/qty)

{
  "invoice": "SINV-26-00042",
  "items": [
    { "item_code": "SD-PR-1000", "qty": 1 }
  ],
  "reason": "1 of 2 units damaged in transit"
}
FieldDescriptionNote
invoiceThe Sales Invoice name returned by create_sales_invoiceRequired
itemsOmit for a full return of every item on the invoice; pass a subset with qty for a partial return
reasonFree text, stored on the credit note's Remarks

Success response (200)

{
  "status": "success",
  "message": "Credit note created and submitted successfully",
  "credit_note": {
    "name": "SINV-26-00043",
    "return_against": "SINV-26-00042",
    "grand_total": -3499,
    "update_stock": 1,
    "docstatus": 1
  }
}
Verified working live (Sept 2026): full return tested against a real invoice — stock returned to exactly its pre-sale quantity, invoice correctly linked via return_against.
Known Issue — Blocking All Orders Right Now
Confirmed from ERPNext's own nginx access logs, plus one more thing that changed since.

1. Wrong URL — missing a slash

Your checkout backend is calling /apimethod/... instead of /api/method/.... Every call 404s before it ever reaches ERPNext's code.

106.222.237.121 - - [24/Sep/2026:09:35:50] "POST /apimethod/ecommerce.apis.create.sales_order" 404
149.255.58.156 - - [23/Sep/2026:07:30:34] "POST /apimethod/ecommerce.apis.create.sales_order" 404
... 23 attempts total over 14 days, all identical 404, all the wrong path
... zero calls ever recorded to the correct /api/method/ path

2. The method itself was renamed (Sept 29, 2026)

The log lines above target ecommerce.apis.create.sales_order — that endpoint has been removed. The BRD calls for Sales Invoices with automatic stock deduction and credit-note returns, which a Sales Order can't do, so it's been replaced with create_sales_invoice and a new create_credit_note. Fixing only the slash and pointing at the old name will still 404. Use the URLs in the sections above.
Every real customer who has checked out in this window got no order record in ERPNext at all. Two fixes needed on the website side, not one.
